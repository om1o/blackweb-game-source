# Smooth animation and reliable starter encounter

The starting-room juvenile is now a real enemy rather than a camera-triggered decoration. It appears after eight seconds of controllable arrival, or six seconds after the phone conversation, without needing the key or vault. It uses the ordinary juvenile profile: 12 HP, 4 bite damage, and three successful 4-damage worn-knife hits to kill. It gets a two-second initial attack grace period. Killing it does not continuously respawn it; restarting or restoring a checkpoint resets the opportunity. Phone dialogue suspends this early enemy, and the later encounter keeps its existing wave.

Luke's base animation now advances once per physics tick before crouch/jump poses and hand IK. Previously its idle-process update could overwrite those physics-authored poses. The full-motion town movie is rendered at 30 fps with deterministic idle/walk skeletal blending, eased walking starts/stops, and continuous head/turn/recoil transitions. It still uses the existing voices, subtitles and skip controls.

Before the first resume, a covered loading step renders ten views of the five rooms, with the real enemy and held-item materials visible. The world stays paused: no phone clock, movement, attacks or damage advance. Camera, item/enemy visibility, flashlight, rendering and pause state are restored before the intro/game resumes. This is performed once per session. The native route harness verifies state restoration. Warm-up took 1.49 seconds in the source run and 1.26 seconds in the first packaged run.

Eleven large web, residue, leather, candy-wrapper and menu-art textures now use GPU compression at their existing resolution. Original artwork remains intact. Text documents and readable interface panels remain lossless. The import settings are tracked so fresh imports preserve this optimization. See [Godot texture import guidance](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html) for the memory/bandwidth tradeoff. Compressed texture payload measurements are distinct from whole-process RAM and FPS.

The native texture-memory audit retained all eleven old/new texture pairs and measured RenderingServer counter deltas: **113,222,967 bytes before → 23,125,720 bytes after**, a **79.6% reduction for these textures**. World textures now have mipmaps; menu art does not need them. DXT block padding can add up to three pixels to GPU storage dimensions. ANGLE image readback decompresses the data, so readback byte counts are not used to claim GPU savings. The audit and per-texture results are in `Godot/tests/texture_memory_audit.gd` and `Evidence/SmoothCombat/texture-memory.json`.

Native rendering remains the Performance preset. A reversal test at 960×540 measured approximately 16.6–16.9 ms medians at native scale, versus 33.1–34.5 ms at 75%/60% scale; returning to native recovered the earlier timing. Removing flashlight shadows did not produce a consistent improvement, so shadows remain. These short paused-view samples isolate rendering; they do not represent live combat or guarantee 60 FPS. Raw samples are in `Evidence/SmoothCombat/scaling.json` and `baseline.json`.

Validation covers real mouse-driven knife timing, recovered-rig crouch/jump poses, juvenile combat, full-house spawn and checkpoint reset, phone safety, door collision/routing, and movie playback. Release-specific native route and portable-package results accompany this document in `Evidence/SmoothCombat`. The previous movie's evidence is archived under `D:/BlackwebHandoffs/Validation/Town3D-d956fe9`.

Passed: locomotion **10/10**, native mouse/knife **16/16**, juvenile combat **31/31**, house combat/spawn/checkpoint **18/18**, native tutorial journey **56/56**, and native movie lifecycle/audio **10/10**. The 42-second, 1,260-frame movie is 15,172,297 bytes. Native movie presentation measured 16.677 ms median and 31.419 ms p95; the maximum 207.58 ms includes synchronous QA image readback. These are playback measurements, not gameplay FPS.

The first full-route build without warm-up averaged 28.205 ms per frame (35.5 FPS), with p95 51.52 ms and a 1,677 ms maximum. The subsequent warmed source run averaged 19.584 ms (51.1 FPS), p95 33.92 ms and maximum 80.662 ms. The first warmed packaged run averaged 18.460 ms (54.2 FPS), p95 33.036 ms and maximum 74.504 ms, completing all nine route legs and eleven knife actions. These are single-machine sequential observations with uncontrolled OS/cache state, not an isolated attribution experiment or a locked-60-FPS guarantee. The first package reports incorrectly labeled their runtime as source because Godot consumes engine flags; their launch scripts used `--main-pack`. The harness now checks the embedded package manifest and accepts `--profile-package` to record the PCK hash directly.

The final provenance-verified PCK run again completed every route leg and eleven knife actions: **49.2 FPS mean**, **16.779 ms median**, **36.682 ms p95**, **67.951 ms maximum**, 2,455 samples. Warm-up took 1.522 seconds and preserved camera, pause/rendering state, health and progression. About 9.6% of measured frames exceeded 33.33 ms, so dips remain. Portable smoke passed **53/53**.
